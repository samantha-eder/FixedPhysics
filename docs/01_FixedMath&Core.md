# 第一层 : 定点数与空间基础设计记录

本层包含 `FixedMath` 目录下的数学库(`FP`、`FPVector2`、`FPVector3`、`FPQuaternion`、`FPRandom`)以及 `FixedPhysics/Core` 下的空间基础结构(`FPTransform`、`FPBounds`)

设计目标 : 脱离浮点数(`float`/`double`), 全部使用 64 位有符号整数(`long`)实现跨平台结果一致的数学与空间运算 

---

## 1. FP(Q32.32 定点数)的核心实现

### 1.1 内存布局
`FP` 内部只有一个 `long Value` 字段 采用 Q32.32 格式 : 
- 高 32 位表示有符号整数部分(范围约 -21亿 ~ +21亿)
- 低 32 位表示小数部分(精度为 $2^{-32} \approx 2.328 \times 10^{-10}$)
- 常数 `1` 对应 `1L << 32`(即 `4294967296L`), `0.5` 对应 `1L << 31` 

### 1.2 加减乘除与防溢出处理
- 加减法 : 直接对底层 `Value` 做整数加减 由于定点数的性能特殊性并没有做checked检查 默认使用者会注意边界情况
- 乘法 : 两个 Q32.32 的 64 位整数直接相乘会产生 128 位结果(小数位变成 64 位), 需要右移 32 位还原为 Q32.32 为了不溢出 `long`, 代码中将两个乘数拆分为高 32 位(整数 `a_h, b_h`)和低 32 位(小数 `a_l, b_l`), 按乘法分配律分开计算后再移位组合, 并检查高 32 位是否超出范围 
- 除法 : 需要计算 `(A << 32) / B` 同样为了避免左移 32 位直接溢出, 将 64 位被除数 `A` 拆成 128 位的高低两部分, 使用 64 次移位减法(二进制长除法)逐位求出商 

### 1.3 无分支位运算技巧 (Abs / Floor / Round / ToInt)
为了减少 CPU 分支跳转, 取整与绝对值均采用算术右移掩码实现 : 
- `Abs(a)` : 利用 `long mask = a.Value >> 63`(正数得 `0`, 负数得 `-1` 即全 `1`), 通过 `(a.Value + mask) ^ mask` 实现无分支取绝对值 
- `Floor(a)` : 补码表示下, 直接将低 32 位清零 `a.Value & INT_MASK` 即为向下取整(例如 `-1.5` 清零小数位后直接变为 `-2.0`) 
- `ToInt()` : C# 默认整数强转是向零截断, 负数在截断前需要加上小数掩码修正 : `(this.Value + ((this.Value >> 63) & DEC_MASK)) >> 32` 
- `Round(a)` : 正数加 `0.5`, 负数加 `0.5 - Epsilon`(即 `Half.Value + (a.Value >> 63)`), 再清零低 32 位 

### 1.4 开方 (Sqrt) 与对数/指数 (Log2 / Exp2)
- `Sqrt` : 采用逐位逼近法(每次从高位拉下 2 个 bit 试商), 先循环 32 次求出整数与前 16 位小数, 再补 0 循环 16 次补全 Q32.32 的全部精度 多次乘除在Q32.32定点数下无任何精度丢失
- `Log2` : 先通过二分移位找到最高位 `1`(`msb`)确定整数部分, 再将尾数归一化到 `[1.0, 2.0)` 区间内, 通过平方法逐位逼近小数部分, 同样保留全部精度
- `Exp2` : 分离整数与小数部分, 小数部分通过预计算的 Q2.62 高精度查找表 `Exp2Table` 累乘, 最后按整数部分移位还原 

### 1.5 三角函数 (CORDIC 算法)
`Sin`、`Cos`、`Atan2` 均采用无分支的 CORDIC(坐标旋转数字计算)算法 : 
- 内部使用 Q2.62 超高精度格式进行 33 轮旋转迭代, 配合预计算的 `AtanTable` 查表逼近角度, 最后四舍五入右移 30 位转回 Q32.32, 彻底避免泰勒展开的高次幂溢出问题

## 2. FPVector3 的 128 位高精度模长与归一化

### 2.1 为什么要避免直接用 SquareMagnitude？
在计算三维向量模长 $\sqrt{x^2 + y^2 + z^2}$ 时, 如果直接用 Q32.32 计算 `x * x`, 当坐标超过 $46340$(即 $\sqrt{2^{31}}$)时, 平方就会超出 Q32.32 的最大表示范围而抛出溢出异常；同理, 如果坐标非常小(如 `0.0001`), 平方后又容易下溢变成 `0` 

### 2.2 解决方案
- `Magnitude` : 内部实现了 `Square128`, 将 `x, y, z` 的平方结果保存在 128 位无符号整数(`ulong res_h, res_l`)中, 带进位相加后再对 128 位大整数直接执行 64 轮逐位开方 这样只要最终模长本身不超出 Q32.32 范围, 中间的平方和就永远不会溢出 
- `Normalize` : 先找出 `|x|, |y|, |z|` 中最大值的最高位 `msb`, 将三个分量等比例左移或右移缩放到第 32 位附近(既防止大向量溢出, 又防止微米级小向量下溢丢失方向), 然后再调用 `Magnitude` 求模并相除

## 3. FPTransform 与空间坐标折跃

`FPTransform` 定义为值类型 `struct`, 包含世界坐标 `Position` 和旋转四元数 `Rotation` 

在物理引擎中, 碰撞盒本身定义在局部空间, 而粗相和推挤发生在世界空间, 核心转换关系如下 : 
- 局部点转世界点 `ToWorldPos(local)` : 先用四元数旋转局部偏移, 再加上世界位置 `Position + (Rotation * local)` 
- 世界点转局部点 `ToLocalPos(world)` : 先减去世界位置, 再乘以四元数的逆(单位四元数的逆即共轭)`Inverse(Rotation) * (world - Position)` 
  (注 : 该转换在第四层 `Sphere vs Box` 以及 `Ray vs Box` 中至关重要, 可将世界空间中的旋转盒 OBB 问题直接降维成局部空间的标准正交 AABB 问题)

## 4. FPBounds (AABB 轴对齐包围盒)

`FPBounds` 同样为值类型 `struct`, 仅保存 `Min` 和 `Max` 两个三维极值点 : 
- `Intersects(other)` : 三轴分离测试 采用闭区间规则, 当边界恰好贴合(`Max.x == other.Min.x`)时视为相交(返回 `true`) 
- `Contains(other)` : 判断当前盒子是否完全包含另一个小盒子, 用于第五层八叉树越界判定与动态 BVH 的肥包围盒(Fat AABB)增量更新检测 
- `GetSurface()` : 计算盒子的表面积 $2(xy + yz + zx)$, 供动态 BVH 插入节点时进行 SAH(表面积启发式)代价评估
