# 第二层：几何形状层设计笔记

本层位于 `FixedPhysics/Shape` 目录下, 包含抽象基类 `FPShape` 以及四个具体形状实现：`FPSphere`、`FPBox`、`FPCapsule`、`FPConvex` 

## 1. 享元模式与核心契约

在物理世界中, 场景里可能同时存在几百颗尺寸相同的子弹或怪物 如果每个碰撞体都保存一份独立的几何顶点数据, 会造成不必要的内存浪费 

因此第二层采用享元模式设计：`FPShape` 只保存形状自身的几何尺寸参数(如半径、半长宽高、局部顶点数组), 不保存任何世界坐标或旋转状态 

任何一个形状只需要实现两个核心抽象方法, 即可自动被物理引擎 粗相检测等处理：
1. `ComputeBounds(FPTransform transform)`：给定形状在世界空间下的最终姿态, 计算其轴对齐包围盒 `FPBounds`(供第五层粗相空间划分使用) 
2. `GetSupportPoint(FPTransform transform, FPVector3 direction)`：给定世界空间下的搜索方向, 返回形状表面在该方向上的最远极点 该搜索方向与获得到的最远极点也作为分离轴与分离面(供第四层 GJK / EPA 算法使用)

## 2. 四种具体形状的实现原理

### 2.1 FPSphere (球体)
球体是各向同性的, 只需要保存一个半径 `Radius` 
- 包围盒计算：球体无论如何旋转, 其在世界三轴上的最大延伸量始终等于半径 构造向量 `r = (Radius, Radius, Radius)`, 包围盒即为 `[Position - r, Position + r]` 
- 支撑点计算：直接从球心出发, 沿着归一化后的搜索方向延伸一个半径长度：`Position + Normalize(direction) * Radius` 
  (注：`FPVector3.Normalize` 内部已处理零向量情况, 外部无需额外调用 `Magnitude` 判断, 避免重复开方) 

### 2.2 FPBox (有向长方体 OBB)
长方体保存局部空间下的半尺寸向量 `Extents`(即半宽、半高、半长) 
- 包围盒计算：当长方体在世界空间发生旋转时, 不能直接用局部 `Extents` 加减中心点 代码中提取当前旋转下的三个世界基向量 `Right`、`Up`、`Forward`, 将 `Extents` 的三个分量分别向世界 X、Y、Z 轴做投影并取绝对值求和：
  `worldExtent.x = |Right.x| * Extents.x + |Up.x| * Extents.y + |Forward.x| * Extents.z`
  (Y、Z 轴同理), 无需遍历 8 个顶点即可一次算出紧凑的 AABB 
- 支撑点计算：先调用 `transform.ToLocalDir(direction)` 将世界搜索方向转入长方体的局部空间；在局部空间中直接根据方向分量的正负号选取极值顶点 `(direction.x > 0 ? Extents.x : -Extents.x, ...)`, 最后用 `ToWorldPos` 转回世界空间 注意这里只依赖方向分量的正负号, 因此无需对输入方向做归一化 但需要注意传入向量的模长不要超过Q32.32定点数的设计上限

### 2.3 FPCapsule (胶囊体)
胶囊体在几何上等价于“一条中心线段与一个球体的闵可夫斯基和”, 内部保存半球半径 `Radius` 与中间圆柱线段的半高 `HalfHeight`(局部空间默认沿 Y 轴竖直摆放) 
- 包围盒计算：由于传入的 `transform.Up` 已经包含了旋转四元数的作用, 直接通过 `Position ± transform.Up * HalfHeight` 即可得到旋转后的上下两个半球球心的世界坐标 `a` 和 `b` 取 `a` 和 `b` 的最小与最大值, 再向外扩充 `(Radius, Radius, Radius)` 即为整个胶囊体的世界 AABB 
- 支撑点计算：分两步完成 第一步比较搜索方向 `direction` 与胶囊体中轴线 `transform.Up` 的点乘符号, 大于等于 0 则取上球心, 小于 0 则取下球心；第二步从选中的球心出发, 加上 `Normalize(direction) * Radius` 即为胶囊体表面的最远点 注:这里的支撑点是某方向上的最远极点 不是图形在某个方向上表面上的那个点 因此支撑点只需要比较搜索方向与中轴线的点乘即可 通过闵可夫斯基和来理解会更容易

### 2.4 FPConvex (自定义凸多面体)
用于支持圆柱体、八面体钻石、以及直接从 Unity `Mesh` 提取顶点的任意不规则凸包, 内部保存局部空间下的顶点数组 `Vertices` 
- 防御性拷贝：构造函数中通过 `(FPVector3[])vertices.Clone()` 复制一份独立的顶点数组, 防止外部代码在创建形状后修改原数组元素, 导致物理世界中的形状在未刷新包围盒的情况下被篡改 
- 包围盒计算：遍历所有局部顶点, 通过 `ToWorldPos` 转为世界坐标, 维护 `Min` 与 `Max` 极值 
- 支撑点计算：为了避免把所有局部顶点都旋转到世界空间(若顶点数为 N 需要做 N 次四元数乘法), 代码中反过来只做 1 次 `ToLocalDir(direction)` 将搜索方向转入局部空间, 然后遍历局部顶点计算点乘 `Dot(Vertices[i], localDir)`, 找出点乘最大的局部顶点后, 再做 1 次 `ToWorldPos` 转回世界坐标返回

## 3. 为什么规则形状要单独实现, 而不全部用 FPConvex 代替？

既然 `FPConvex` 只需要遍历顶点就能算出包围盒与支撑点, 为什么还要单独写 `FPSphere`、`FPBox` 和 `FPCapsule`
原因在于曲面精度与计算复杂度：
1. 球体与胶囊体具有光滑曲面, 在数学上有无穷多个表面点 如果用多面体顶点去近似球面, 不仅失去了真正的圆弧平滑滚动特性(变成有棱角的骰子), 而且顶点数越多, 每次 `GetSupportPoint` 遍历点乘的开销就越大($O(N)$) 而解析公式只需要 $O(1)$ 的常数运算且精度绝对平滑 
2. 长方体虽然只有 8 个顶点, 但通过符号判断选取极点以及三轴投影算包围盒, 比遍历 8 个顶点做四元数变换更快 因此规则几何体走解析公式, 不规则模型才使用 `FPConvex`
